# Complete reservoir admission program

Run `python -B tools/fleet_admission.py --output outputs/<fresh_directory>` to prepare a fresh admission review. The final verified snapshot is `outputs/fleet_admission_verified_20261012`; the earlier preparation is retained separately. Every active manifest member receives a status, evidence and next action. Tuyen remains the sole requested exclusion. This tool estimates calibration-only percentile boxes and checks constraint feasibility; it never calls a model or optimizer.

The new review admits 20 reservoirs on existing calibration evidence: nine under strict rejection and eleven under an explicit nearest-previous-storage policy. The policy uses previous simulated storage and the existing deterministic minimum-storage tie rule. It is a provisional numerical convention, not a recovered reservoir operating rule. Admission does not use validation scores or validation feasibility.

The remaining 21 are still part of the program: Bull Lake has cached reviewed interval results; ten need an explicit source-assumption review; three have an incompatible empirical parameter box; three cannot satisfy the proposed critical-gap constraint within their current box; McGregor has a constrained initialization witness requiring simulation preflight; Brazeau needs its forcing adapter; Trinity and Ghost need source profiles.

Three impossible empirical boxes were identified for Fort Peck, Falcon and Bennett. The review retains the original P5–P35/P35–P75/P75–P95 bounds, configured capacity and operating floor. It does not sort estimated targets, clip measurements, inflate capacity or widen percentile limits to obtain success. Other reservoirs with initially invalid generalized targets have an ordered candidate inside their empirical box, but source flags still require interpretation.

For initialization, `ordered_candidate` constructs a mathematical witness within each month's unchanged bounds. The additional `Sc - Sd >= dt * Qc` constraint prevents the known upward release jump at the critical boundary. It is a sufficient constraint for removing that particular discontinuity, not a necessary condition for every trajectory to succeed. Its incompatibility does not prove every parameter trajectory fails. Chardara, Kayrakkum and Tyuyamuyun need a separately declared bounds/timestep experiment or another feasible initialization approach. No hydrological equation or timestep changes here.

Witnesses are not calibrated parameters and have not been simulated. The expanded 60-job calibration plan is explicitly nonexecutable through the old fleet runner, which hardcodes strict rejection and asserts a feasible generalized baseline. The next execution implementation must use the existing `RootPolicyCalibrationObjective`, record the declared policy in checkpoint identity, and run calibration-only initialization preflight. A failed held-out simulation must remain a reporting failure rather than changing admission or selecting parameters.

Each snapshot contains `admission.json`, `reservoir_status.csv`, `work_queue.json`, `calibration_plan.json`, a README and a verification receipt. Source flags and original reasons remain visible even when the strict-baseline restriction is relaxed. All numerical modules, canonical inputs, prior outputs and checkpoints remain unchanged. Fixed budgets do not establish convergence or physical source certification.

`python -B tools/verify_fleet_admission.py --output outputs/<snapshot>` independently checks the saved plan, reconstructs the percentile bounds through the public estimator, validates witnesses through `ReservoirParameters`, and checks admission evidence and hashes. The final snapshot matches percentile estimates for all 41 reservoirs, validates 70 ordered/gap-constrained witnesses and confirms 11 additional root-policy admissions. These are arithmetic checks, not new simulation runs.
